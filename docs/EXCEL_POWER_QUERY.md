# Refreshing the Excel export from the snapshot API

The **Download Excel** button on the dashboard produces a genuine `.xlsx` with
three sheets (`Summary`, `Option Chain`, `Raw Data`) built from the newest
validated NSE snapshot stored in Supabase. It is generated by the hosted server,
so it works from any browser with no Python, no local helper and no repository
clone.

The workbook follows the panel's settings:

- **symbol** and **expiry** choose the snapshot;
- **strike range** (`all`, 10/20/30 around ATM) trims the `Option Chain` sheet;
- **import fields** (OI, change in OI, volume, IV, LTP, price change, bid/ask)
  choose its columns;
- the `Raw Data` sheet always keeps every strike and every source field, so a
  narrow view never loses data.

That file is still a **point-in-time snapshot**. A plain `.xlsx` downloaded from a
browser cannot rewrite itself, and this project does **not** ship a hidden
database connection inside the file. If you want a workbook that refreshes in
place, connect it to the read-only snapshot API with **Power Query**, which is
what this guide does.

> **What refresh means here.** `Data > Refresh All` re-queries this dashboard's
> API, which re-reads the stored Supabase row. It does **not** contact NSE. Only
> the collector (`worker/bridge_worker.py`) fetches NSE, and only while it is
> running. If the collector has stopped, refreshing the workbook returns the same
> old snapshot, and the `status` column says `Last Close` or `Stale` - it never
> pretends to be live. See
> [`HOSTED_DEPLOYMENT.md`](HOSTED_DEPLOYMENT.md) for the hosted collector.

## 1. Point the queries at your deployment

Use the public HTTPS origin of the deployed dashboard. For local development the
same steps work with `http://localhost:3000`:

```bash
cd web
npm run dev        # http://localhost:3000
# or, for a production build:
npm run build && npm start
```

The API needs read credentials in the server environment:

```ini
SUPABASE_URL=https://<project>.supabase.co
SUPABASE_ANON_KEY=<anon public key>
# or the NEXT_PUBLIC_* equivalents used by the dashboard
```

Only the **anon** key is used. The API never reads or returns a service-role key.

Check it quickly in a browser:

- <https://your-app.example/api/option-chain/expiries?symbol=NIFTY>
- <https://your-app.example/api/option-chain?symbol=NIFTY&expiry=27-Oct-2026&format=json>
- <https://your-app.example/api/option-chain?symbol=NIFTY&expiry=27-Oct-2026&format=csv>
- <https://your-app.example/api/health>

If the expiry is unknown, omit it and the API returns the newest snapshot for
that symbol: `/api/option-chain?symbol=NIFTY&format=csv`. To build a picker,
read the real expiries from `/api/option-chain/expiries?symbol=NIFTY` instead of
typing dates by hand.

## 2. Create the parameters

In Excel: **Data > Get Data > From Other Sources > Blank Query**, then
**Home > Manage Parameters > New Parameter**. Create them as **Text**:

| Name | Example value | Notes |
| --- | --- | --- |
| `BaseUrl` | `https://your-app.example` | origin only, no trailing slash |
| `pSymbol` | `NIFTY` | `NIFTY`, `BANKNIFTY`, `FINNIFTY` |
| `pExpiry` | `27-Oct-2026` | must match the snapshot expiry exactly, e.g. `27-Oct-2026` |
| `pRange` | `all` | optional: `all`, `10`, `20`, `30` (strikes either side of ATM) |
| `pFields` | `all` | optional: `all`, or a comma list of `oi,oi_change,volume,iv,ltp,price_change,bid_ask` |

Rename the queries `BaseUrl`, `pSymbol`, `pExpiry`, `pRange`, `pFields` so the
query below resolves them as steps. `pRange` and `pFields` are optional; leaving
them out of the query (or setting `pRange = "all"` and `pFields = "all"`) gives
the complete chain with every column.

The same parameters apply to the workbook endpoint, so a macro can call
`/api/option-chain/export?symbol=NIFTY&expiry=27-Oct-2026&range=10&fields=ltp,oi`
and receive exactly the same view the dashboard would download.

## 3. Recommended query: CSV

CSV repeats the snapshot metadata on every row (`symbol`, `expiry`, `spot`,
`pcr`, `max_pain`, `total_ce_oi`, `total_pe_oi`, `nse_timestamp`,
`snapshot_updated_at`, `status`), so a single table is enough for pivots.

Open **Data > Get Data > From Other Sources > Blank Query**, then
**Home > Advanced Editor** and paste:

```m
let
    Url = BaseUrl & "/api/option-chain?symbol=" & pSymbol
        & "&expiry=" & pExpiry & "&format=csv"
        & "&range=" & pRange & "&fields=" & pFields,

    // ManualStatusHandling lets us read the HTTP status instead of getting an
    // opaque "DataFormat.Error" when the snapshot is missing (404), the range is
    // invalid (400), the row is too large (413) or the API is rate-limited (429).
    Response = Web.Contents(
        BaseUrl,
        [
            RelativePath = "/api/option-chain",
            Query = [
                symbol = pSymbol, expiry = pExpiry, format = "csv",
                range = pRange, fields = pFields
            ],
            ManualStatusHandling = { 400, 404, 413, 429, 502, 503 }
        ]
    ),
    Status = Value.Metadata(Response)[Response.Status],
    Body = if Status = 200 then Response
        else error Error.Record(
            "NSE snapshot API",
            "HTTP " & Text.From(Status) & " - see " & Url,
            "404 = no snapshot, 429 = slow down (export allows 12/min), "
                & "503 = read credentials missing, 502 = snapshot unreadable"
        ),

    Source = Csv.Document(
        Body,
        [ Delimiter = ",", Encoding = 65001, QuoteStyle = QuoteStyle.Csv ]
    ),
    Promoted = Table.PromoteHeaders(Source, [ PromoteAllScalars = true ]),

    // Only the metadata columns are text; everything else (STRIKE, CE_*, PE_*)
    // is numeric, so Excel can sort, filter and chart it.
    TextColumns = { "symbol", "expiry", "nse_timestamp", "snapshot_updated_at", "status" },
    Typed = Table.TransformColumnTypes(
        Promoted,
        List.Transform(
            Table.ColumnNames(Promoted),
            each { _, if List.Contains(TextColumns, _) then type text else type number }
        )
    )
in
    Typed
```

Name the query `NseOptionChain`, then **Close & Load To... > Table** on a new
worksheet.

## 4. Alternative query: JSON

Use this if you want the snapshot metrics once, rather than repeated per row.
It returns the same data as `meta`, `fields` and `chain`.

```m
let
    Url = BaseUrl & "/api/option-chain?symbol=" & pSymbol
        & "&expiry=" & pExpiry & "&format=json"
        & "&range=" & pRange & "&fields=" & pFields,

    Response = Web.Contents(
        BaseUrl,
        [
            RelativePath = "/api/option-chain",
            Query = [
                symbol = pSymbol, expiry = pExpiry, format = "json",
                range = pRange, fields = pFields
            ],
            ManualStatusHandling = { 400, 404, 413, 429, 502, 503 }
        ]
    ),
    Status = Value.Metadata(Response)[Response.Status],
    Json = if Status = 200 then Json.Document(Response)
        else error Error.Record(
            "NSE snapshot API",
            "HTTP " & Text.From(Status) & " - see " & Url,
            "404 = no snapshot, 429 = slow down, 503 = read credentials missing, 502 = snapshot unreadable"
        ),

    // "fields" is exactly the set of columns this query returns, so the expand
    // step adapts when you change pFields (no broken hard-coded column list).
    FieldNames = List.Distinct(Json[fields]),
    Rows = Table.FromList(Json[chain], Splitter.SplitByNothing(), { "Record" }),
    Expanded = Table.ExpandRecordColumn(
        Rows, "Record", FieldNames, FieldNames, MissingField.UseNull
    ),

    // Attach the snapshot metadata once per row so the table is self-describing.
    MetaColumns = {
        { "snapshot_symbol", each Json[meta][symbol], type text },
        { "snapshot_expiry", each Json[meta][expiry], type text },
        { "snapshot_spot", each Json[meta][spot], type number },
        { "snapshot_pcr", each Json[meta][pcr], type number },
        { "snapshot_max_pain", each Json[meta][max_pain], type number },
        { "snapshot_total_ce_oi", each Json[meta][total_ce_oi], type number },
        { "snapshot_total_pe_oi", each Json[meta][total_pe_oi], type number },
        { "nse_timestamp", each Json[meta][nse_timestamp], type text },
        { "snapshot_updated_at", each Json[meta][snapshot_updated_at], type text },
        { "snapshot_status", each Json[meta][status], type text },
        { "strike_range_label", each Json[meta][strike_range_label], type text },
        { "fields_label", each Json[meta][fields_label], type text },
        { "strike_count", each Json[meta][strike_count], type number }
    ],
    WithMeta = List.Accumulate(
        MetaColumns, Expanded,
        (state, column) => Table.AddColumn(state, column{0}, column{1}, column{2})
    )
in
    WithMeta
```

## 5. Credentials

The API is public read-only, so no credentials are needed at the Excel end:

1. When Excel asks, choose **Anonymous** authentication.
2. If asked about privacy levels, **Ignore** is fine for a localhost API (or
   organise the file into a single privacy level).

Do not add your Supabase URL or keys to a Power Query query - the dashboard
server already holds the anon key, and credentials inside a workbook get shared
with the file.

## 6. Refresh

- **Data > Refresh All** (or **Refresh** in the Queries & Connections pane)
  re-runs the query and reloads the table.
- Change `pSymbol` / `pExpiry` / `pRange` / `pFields` in **Data > Queries &
  Connections** and refresh to switch instrument, expiry or view - no new
  workbook needed.
- **Data > Queries & Connections > Properties** lets you set *Refresh every N
  minutes*, but keep it slower than the collector interval (30 s by default) and
  remember the dashboard's own auto-refresh (1/5/15/30 min) only polls the API
  for the browser tab; it does not refresh this workbook.
- Refreshing while the market is closed returns the same close snapshot; the
  `status` column will read `Last Close`. That is honest, not a failure.
- Refreshing re-reads the API, so it also respects the API's rate limit
  (120 reads/minute per IP). A single Refresh All touches the API once.

### Refreshing the whole workbook

**Download Excel** always produces the same three sheets. The `Option Chain`
sheet is the requested strike/field view; `Raw Data` is the complete snapshot.
Neither sheet updates by itself — only a Power Query table does. If you need a
live summary, build it on a new sheet from the `NseOptionChain` table as shown in
§7.

### Power BI / Power Automate / scheduled refresh

The same `Web.Contents` queries work in Power BI Desktop. For a scheduled refresh
in the Power BI service or Power Automate, the API must be reachable from
Microsoft's cloud, which means deploying `web/` (for example to Vercel) and
setting `SUPABASE_URL` + `SUPABASE_ANON_KEY` there. `http://localhost:3000` is
only reachable from your own machine.

## 7. What does not refresh

Inside the downloaded `_snapshot.xlsx`:

- `Summary`, the static `Option Chain` sheet and `Raw Data` are frozen
  point-in-time records, including the `Snapshot status` cell. They are useful as
  an audit trail and will not change.
- Only a table created by Power Query (as above) refreshes.
- If you want a live summary, build it on a new sheet with normal formulas over
  the `NseOptionChain` table, e.g.
  `=INDEX(NseOptionChain[nse_timestamp],1)` or a `MAXIFS`/`XLOOKUP` over
  `STRIKE` values, instead of relying on the generated Summary sheet.

## 8. Troubleshooting

| Symptom | Cause / fix |
| --- | --- |
| `HTTP 404` | No snapshot for that symbol/expiry. Check the expiry string and that the collector has pushed data. |
| `HTTP 503` | `SUPABASE_URL` / `SUPABASE_ANON_KEY` are not set in the server environment. |
| `HTTP 502` | Supabase was unreachable, or the stored row is incomplete. The dashboard logs the real error server-side. |
| `HTTP 400` | Bad `symbol`, `expiry`, `format`, `range` or `fields` in the query. |
| `HTTP 413` | The stored snapshot exceeds the API's size guard (5,000 strikes for JSON/CSV, 2,000 for a workbook). Investigate the collector output. |
| `HTTP 429` | Rate limit hit (12 exports/minute, 120 reads/minute per IP). Wait `Retry-After` seconds; do not loop Refresh All. |
| `DataSource.Error` / connection refused | The dashboard is not running, or `BaseUrl` points at the wrong origin. |
| Table is empty | The API returned a snapshot with no strikes - treat it as broken data, not a market event. |
| Numbers show as text | A stray character in a numeric column; delete the query and re-paste the code above. |
| Status says `Stale` | The stored snapshot is older than the current session, or its NSE timestamp is outside trading hours. Check the hosted collector (see `HOSTED_DEPLOYMENT.md`). |
| `fields` expansion errors | `pFields` changed but the query was not refreshed; `FieldNames` reads `Json[fields]`, so refresh the query rather than editing columns by hand. |
